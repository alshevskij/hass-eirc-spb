Неофициальная интеграция для [Home Assistant](https://www.home-assistant.io/), подключающаяся к личному кабинету [ЕИРЦ Санкт-Петербурга / ПСК](https://ikus.pesc.ru/) (IKUS). Интеграция получает показания приборов учёта и задолженность, а также предоставляет экспериментальную возможность передавать показания счётчиков из Home Assistant.

## ВАЖНО!
> **Передача показаний — экспериментальная функция (бета).** Она прошла ограниченное тестирование на реальном лицевом счёте, но пока не проверена на достаточном количестве аккаунтов, приборов учёта и вариантов конфигурации. Не полагайтесь на неё как на гарантированно надёжный способ передачи данных. Перед использованием ознакомьтесь с разделом [«Передача показаний: статус и риски»](#передача-показаний-статус-и-риски).

## Возможности

### Счётчики и задолженность
- Автоматическое получение доступных лицевых счетов.
- Отдельные устройства Home Assistant для каждого лицевого счёта.
- Сенсоры текущих показаний ХВС, ГВС и электроэнергии.
- Сенсор задолженности по каждому лицевому счёту.
- Отслеживание появления новой текущей квитанции и уведомление Home Assistant со ссылкой на PDF.
- Открытие PDF квитанции в браузере без сохранения временного UUID IKUS.
- Кнопка «Квитанция: открыть PDF» на устройстве лицевого счёта для ручного открытия актуального документа.
- Дата последних показаний и текущий период приёма — в атрибутах сенсоров.
- Автоматическое обновление данных каждые 30 минут.

### Передача показаний (экспериментально)
- Поле ввода нового значения для каждого регистра счётчика.
- Отдельная кнопка отправки показаний.
- Поддержка ХВС, ГВС и электроэнергии; название электрического счётчика учитывает тип прибора (например, «Круглосуточный»).
- После отправки интеграция перечитывает данные IKUS и сверяет фактически сохранённое значение.
- Ответ API `false` сам по себе не считается отказом: результат определяется по повторному чтению, поскольку IKUS может сохранить показания и вернуть `false`.

## Установка

### Через HACS (рекомендуется)

[![Открыть репозиторий в HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=alshevskij&repository=hass-eirc-spb&category=integration)

1. Установите [HACS](https://hacs.xyz/), если он ещё не установлен.
2. Откройте HACS → **Интеграции**.
3. Через меню в правом верхнем углу откройте **Пользовательские репозитории**.
4. Добавьте `https://github.com/alshevskij/hass-eirc-spb` с категорией **Integration**.
5. Найдите **ЕИРЦ СПб: Личный кабинет** и установите интеграцию.
6. Перезапустите Home Assistant.

Или нажмите на значок **Открыть репозиторий в HACS** выше — ссылка перенаправит в HACS вашего Home Assistant.

### Вручную

1. Скопируйте каталог `custom_components/eirc_spb` в `/config/custom_components/`.
2. Перезапустите Home Assistant.

## Настройка

1. Откройте **Настройки → Устройства и службы**.
2. Нажмите **Добавить интеграцию** и найдите **ЕИРЦ СПб: Личный кабинет**.
3. Введите номер телефона и пароль от личного кабинета IKUS.
4. Если потребуется, введите код подтверждения из письма на привязанную электронную почту.
5. Выберите один или несколько лицевых счетов.

Пароль и токены авторизации хранятся в конфигурационной записи Home Assistant.

## Сущности

Для каждого выбранного лицевого счёта создаётся отдельное устройство. В зависимости от состава приборов учёта будут доступны:

| Прибор / данные | Сущность |
|---|---|
| Холодная вода | **ХВС: текущие показания** |
| Горячая вода | **ГВС: текущие показания** |
| Электроэнергия | **Энергия (тип прибора): текущие показания** |
| Задолженность | **Задолженность** |
| Платёжный документ | **Квитанция: открыть PDF** |

Для каждого регистра также создаются поле **«ввод показаний»** и кнопка **«передать показания»** с соответствующим названием прибора. Например, для однотарифного счётчика электроэнергии это будут «Энергия (Круглосуточный): ввод показаний» и «Энергия (Круглосуточный): передать показания».

Атрибуты сенсоров счётчиков содержат серийный номер, дату последних принятых показаний, тип регистра, статус прибора и сведения о периоде приёма показаний.

## Платёжные документы

Интеграция отслеживает изменение идентификатора текущей квитанции (`bill_id`) отдельно для каждого выбранного лицевого счёта. При первом запуске текущая квитанция сохраняется как исходная — уведомление о старом документе не создаётся. Когда IKUS публикует новую квитанцию, Home Assistant создаёт постоянное уведомление со сведениями о документе и ссылкой **«Открыть PDF»**. Для ручного открытия актуальной квитанции на устройстве лицевого счёта также доступна кнопка **«Квитанция: открыть PDF»** — она создаёт такое же уведомление.

PDF выдаётся через защищённый HTTP-адрес Home Assistant с ограниченным сроком действия ссылки. При каждом открытии интеграция заново запрашивает у IKUS временный UUID и по нему загружает PDF. UUID не сохраняется, поскольку IKUS формирует новый идентификатор при каждом запросе. Документ открывается inline (`application/pdf`), поэтому браузер может показать его в отдельной вкладке, как при скачивании с сайта.

Также отправляется событие Home Assistant `eirc_spb_new_bill` с полями `account_id`, `bill_id`, `period`, `amount` и `url`; его можно использовать в собственных автоматизациях.

**Ограничение API:** IKUS предоставляет интеграции только текущую квитанцию. После появления следующего документа ссылка на предыдущую квитанцию может перестать работать, поскольку старый документ уже нельзя запросить через используемый endpoint. Уведомление и ссылка предназначены для открытия актуальной квитанции.

## Передача показаний

## ВАЖНО!
> **Функция находится в бета-тестировании.** Используйте её только после проверки текущих показаний в официальном личном кабинете. Если вы не готовы самостоятельно перепроверять результат, передавайте показания через официальный сайт или приложение IKUS.

1. Откройте устройство нужного лицевого счёта.
2. В сущности **«…: ввод показаний»** укажите новое значение.
3. Ещё раз сверьте введённое число с дисплеем счётчика и убедитесь, что выбран правильный прибор и регистр.
4. Нажмите соответствующую кнопку **«…: передать показания»** один раз.
5. Дождитесь завершения запроса и обновления данных.
6. Проверьте новое значение в Home Assistant и обязательно подтвердите его появление в официальном личном кабинете IKUS.

Интеграция не повторяет POST автоматически. Если после отправки возникла ошибка, тайм-аут или значение не обновилось, **не нажимайте кнопку повторно сразу**: сначала проверьте личный кабинет IKUS. Запрос мог быть обработан сервером, даже если Home Assistant не получил подтверждение.

### Передача показаний: статус и риски

Передача реализована на основе найденного и проверенного на практике endpoint API IKUS. В ходе разработки удалось отправить реальные показания ХВС, ГВС и электроэнергии на одном лицевом счёте и увидеть сохранённые значения при повторном чтении. Это подтверждает работоспособность базового сценария, но не является полноценным тестированием для всех пользователей и типов оборудования.

На текущем этапе остаются следующие ограничения:

- **Ограниченная выборка тестов.** Проверка проводилась на одном лицевом счёте и конкретных приборах учёта. Не подтверждена совместимость со всеми моделями счётчиков, несколькими регистрами, многотарифными конфигурациями и особенностями других лицевых счетов.
- **Неофициальный и недокументированный API.** Интеграция использует внутренний API веб-кабинета IKUS. Его поведение, форматы запросов и правила валидации могут измениться без уведомления.
- **Неоднозначный ответ сервера.** В реальных тестах IKUS сохранял показания ХВС и ГВС, возвращая при этом `false`; для электроэнергии в аналогичном сценарии был получен `true`. Поэтому ответ POST нельзя считать надёжным подтверждением результата. Интеграция пытается проверить сохранение отдельным запросом на чтение, но это зависит от доступности и актуальности данных API.
- **Задержка обновления данных.** Сервер может принять показания, но не сразу отобразить их в ответе на повторный запрос. В таком случае интеграция может не подтвердить отправку, хотя операция уже выполнена.
- **Риск повторной передачи.** При сетевом сбое или тайм-ауте Home Assistant может не узнать, был ли обработан запрос. Автоматического повтора нет намеренно: повторная отправка без проверки может привести к дублированию или нежелательному результату.
- **Операцию нельзя отменить средствами интеграции.** После принятия показаний сервером исправление или отзыв значения может потребовать обращения к официальному сервису и зависит от его правил.
- **Правила приёма показаний контролирует IKUS.** Допустимые даты, периоды, диапазоны и проверки могут зависеть от лицевого счёта и прибора. Интеграция не может гарантировать, что сервер примет любое введённое значение.

**Рекомендации:**
- Пока функция тестируется, безопаснее использовать официальный личный кабинет для регулярной передачи показаний.
- Не используйте автоматизации, которые отправляют показания без ручной проверки.
- Перед нажатием кнопки проверьте лицевой счёт, прибор, регистр и значение.
- После отправки проверяйте результат именно в официальном IKUS, а не только по уведомлению или сенсору Home Assistant.
- При неопределённом результате не отправляйте показания повторно, пока не выясните статус первой попытки.

Статус функции будет пересмотрен после дополнительных проверок на разных лицевых счетах и типах приборов учёта, а также после накопления обратной связи пользователей.

## Безопасность и ограничения

Интеграция использует API IKUS, к которому обращается веб-личный кабинет. API и его структура могут измениться без предупреждения.

Условия использования IKUS могут ограничивать автоматизированное взаимодействие. Техническая доступность API сама по себе не означает разрешения на автоматизацию. Перед регулярным использованием проверьте действующие условия сервиса и применимые ограничения.

Не публикуйте журналы, HAR-файлы, cookies, токены, номера телефонов, ФИО, адреса и идентификаторы лицевых счетов. Перед созданием Issue удалите персональные данные.

## Решение проблем

Если интеграция работает некорректно, включите отладочное логирование:

```yaml
logger:
  default: info
  logs:
    custom_components.eirc_spb: debug
```

Журналы доступны в **Настройки → Система → Журналы**. При создании [Issue](https://github.com/alshevskij/hass-eirc-spb/issues) приложите только релевантные строки, предварительно удалив личные данные и токены.
